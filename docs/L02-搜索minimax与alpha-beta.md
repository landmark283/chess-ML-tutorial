## K2.1｜博弈树与递归

### 为什么要它

"下棋"这件事，人脑里是这样想的：*"我走这里，他大概走那里，然后我……"* —— 你其实在脑子里**展开了一棵树**。

这个知识点的全部内容是：**把那个模糊的"如果……那么……"变成一棵可以计算的树**。树一旦立起来，"选最好的一步"就变成了"在树上找一个最优值" —— 一个纯技术问题。

### 树是怎么长出来的

```
                        [空盘]  ← 根（root）：还没走
                  X 走 /  X 走 \  ...
              ┌────────┐   ┌────────┐
              │  X . . │   │  . X . │  ← 第 1 层：X 的所有走法
              └────────┘   └────────┘
             O走/  \O走      O走/  \O走
          [X..]  [X..]     [.X.]  [.X.]  ← 第 2 层：O 的所有应对
             …      …        …      …
                              ↓
                    [X O X / O X O / X .]  ← 叶子：分出胜负或下满
```

五个术语，一次说清：

| 术语            | 意思                | 在代码里是什么                                        |
| ------------- | ----------------- | ---------------------------------------------- |
| **节点**（node）  | 一个局面              | `cells` 这个 9 个格子的列表                            |
| **边**（edge）   | 一步走法              | 往某个空格里落一个子                                     |
| **根**（root）   | 当前局面              | 你要做决定的那个局面                                     |
| **叶子**（leaf）  | 没法再走的局面（有人赢 / 下满） | `winner(cells) is not None` 或 `is_full(cells)` |
| **深度**（depth） | 从根往下走了几步          | 递归的参数 `depth`                                  |

**关键观察**：整棵树的形状，由**规则**决定。所以 L01 的 31 个测试是这棵树的地基 —— 规则错一点，整棵树都是歪的。

### 一个具体的数字：这棵树到底有多大

我穷举过（`src/part2_search/measure.py`）：

```
合法局面总数（含空盘）：5478
可能的对局总数：        255168
终局分布：X 赢 131184 / O 赢 77904 / 平局 46080
穷举一遍耗时：          0.41 秒
```

**"只有 5478 个局面"是井字棋给我们的奢侈品。** 它意味着我们可以把整棵树搜完，得到一个**数学上绝对正确**的答案。后面换成五子棋，这个奢侈品就没了 —— 那时我们才知道自己失去了什么。

### 递归：让树自己长出来

树的代码几乎是递归的天然形状：

```python
def walk(cells, depth):
    if 这是叶子(cells):        # ← 递归基：不再往下
        return 结果(cells)
    for 每一步 in 所有走法(cells):
        落子(每一步)
        子结果 = walk(cells, depth + 1)     # ← 递归步：问题变小一层
        悔棋(每一步)                        # ← ⚠️ 关键！试完必须撤回
    return 合并(所有子结果)
```

> **L01 埋的伏笔在这里炸开**：`悔棋(每一步)` 那一行。
> 搜索一秒要试几十万次走法。如果每次都用 `copy.deepcopy(board)` 拷一份新棋盘，光复制就够慢了；更糟的是如果**忘了撤回**，棋盘会被试走的子污染，后面算的全是错的 —— 而且不报错。
> 这就是我们在 L01 把 `history` 单独存一份的原因：**落子 → 递归 → 撤回**是原地操作，快到可以忽略。

**递归三要素在搜索里的具体样子**（L01 附录 A.5 讲过概念，这里是落地）：

| 递归三要素             | 在搜索里             |
| ----------------- | ---------------- |
| **递归基**（什么时候不往下）  | 有人赢 / 棋盘满了       |
| **递归步**（怎么变小）     | 落一个子，`depth + 1` |
| **合并**（小答案怎么变大答案） | 下一步讲：max 或 min   |

### 一个"不写代码"的小实验

拿纸笔（或脑子）展开这个局面：

```
   X · ·
   · O ·
   · · ·
```

**要求**：从"轮到 X"开始，展开**两层**（X 的所有走法 + 每个走法下 O 的所有应对）。

<details>
<summary>你应该得到什么</summary>

- X 有 7 个空格可走（0,1,2,3,5,6,7,8），所以第 1 层有 **7 个节点**
- 每个节点下，O 有 6 个空格可走，所以第 2 层有 7 × 6 = **42 个节点**

**这就是"分支因子"的直观含义**：井字棋开局有 9 个走法、之后大约 7~8 个，平均分支因子 ≈ 5（因为有赢棋会提前终止）。
两层就 42 个节点；如果每层平均 5 个分支，**10 层就是 5¹⁰ ≈ 976 万个节点**。这个数字的恐怖，K2.5 再看。

</details>

## K2.2｜minimax：你取最大，对手取最小

### 为什么要它

树立起来了，但"哪个走法好"还没有定义。minimax 的全部内容是一句大实话：

> **你会选对你最有利的一步；你的对手也会选对他最有利的一步（也就是对你最不利的一步）。**

把这句话翻译成数字：我们给每个叶子打一个分，**分越高对 X 越有利**：

```
X 赢   → +1
平局   →  0
O 赢   → -1
```

那么往回推（这叫做**回传 / backup**）：

```
轮到 X 的节点 → 取所有子节点里的 【最大】值   （X 挑对自己最好的）
轮到 O 的节点 → 取所有子节点里的 【最小】值   （O 挑对 X 最差的）
```

根节点的值，就是"**在双方都最优的前提下，这个局面的最终结果**"。

### 一个 6 个节点的小树，手算一遍

```
                    [根: X 走]
                   ╱          ╲
             [A: O 走]        [B: O 走]
            ╱        ╲        ╱      ╲
       叶:+1       叶:-1   叶:0     叶:+1
```

从下往上算：

| 步骤  | 算谁        | 怎么算                 | 结果     |
| --- | --------- | ------------------- | ------ |
| 1   | 节点 A（O 走） | O 取最小：`min(+1, -1)` | **-1** |
| 2   | 节点 B（O 走） | O 取最小：`min(0, +1)`  | **0**  |
| 3   | 根（X 走）    | X 取最大：`max(-1, 0)`  | **0**  |

**结论**：这个局面的价值是 **0（平局）**，X 应该走 **B**。

注意第 3 步：X 有两个选择，A 的结果是"我输"，B 的结果是"平局"。**X 当然走 B。** minimax 做的就是这件事，只不过它把"我输/平局/我赢"换成了 -1 / 0 / +1。

### 为什么这叫 minimax

```
max  ←   你的回合，你要最大化
min  ←   对手回合，他要最小化（相对你）
max
min
...
```

一个"max 层、min 层交替往下"的树。名字就是这么来的。

### 代码：最直观的版本（也是最长的那种）

`src/part2_search/engine.py` 里的 `MinimaxAgent`：

```python
def _minimax(self, cells, depth):
    self.stats.nodes += 1
    w = winner(cells)
    if w is not None:
        return 1 if w == X else -1          # 终局：X 赢 +1，O 赢 -1
    if is_full(cells):
        return 0                            # 平局

    if depth % 2 == 0:                      # X 走
        best = -2
        for i in range(N_CELLS):
            if cells[i] == EMPTY:
                cells[i] = X
                best = max(best, self._minimax(cells, depth + 1))
                cells[i] = EMPTY            # ← 撤回
        return best
    else:                                   # O 走
        best = 2
        for i in range(N_CELLS):
            if cells[i] == EMPTY:
                cells[i] = O
                best = min(best, self._minimax(cells, depth + 1))
                cells[i] = EMPTY
        return best
```

**它的三个特点**（也是它的三个缺点）：

| 特点          | 说明                                          |
| ----------- | ------------------------------------------- |
| ✅ 最贴近直觉     | 和刚才手算的表格一一对应                                |
| ❌ 代码重复      | 两个分支的循环**一模一样**，只有 `max`/`min` 不同           |
| ❌ **视角不统一** | 返回值永远"以 X 为准"。如果让这个函数评估"轮到 O 的局面"，你还得在脑子里换算 |

第三个缺点才是要害。看 `MinimaxAgent.choose()`：

```python
if me == X:
    best = max(v for v, _ in scored)
else:
    best = min(v for v, _ in scored)
```

**调用的人必须记得"我是谁、该取 max 还是 min"**。这种"记在脑子里"的约定，是 bug 的重灾区 —— 而 K2.3 会把它彻底消灭。

## K2.3｜negamax：代码砍一半，结果一个不差

### 为什么要它

minimax 有两个毛病：代码重复、视角不统一。negamax 用一个非常漂亮的观察同时解决它们：

> **在零和博弈里，一个局面对我有多好，就等于对对手有多差的相反数。**

用公式说：

```
我的收益 = −（对手的收益）
```

所以"轮到对手的节点，我要取 min"，可以改写成：

```
轮到对手的节点：他取 max，我把他 max 出来的值取负
```

**于是所有节点都变成"取最大"**，只是每一层多一个负号：

```python
value = max( -negamax(child)  for child in children )
```

### 手算一遍（还是那棵小树）

```
                    [根: X 走]
                   ╱          ╲
             [A: O 走]        [B: O 走]
            ╱        ╲        ╱      ╲
       叶:+1       叶:-1   叶:0     叶:+1
```

negamax 的规则是：**站在"该走的人"的立场，永远取他所有走法里的最大值，而子节点的值要取负。**

从叶子往回算（每个节点值 = 该走的人视角下的分数）：

| 节点  | 该谁走 | 子节点值      | 取负后的候选     | 该节点的值  |
| --- | --- | --------- | ---------- | ------ |
| A   | O   | +1, -1    | -1, **+1** | **+1** |
| B   | O   | 0, +1     | 0, **-1**  | **0**  |
| 根   | X   | A=+1, B=0 | -1, **0**  | **0**  |

根节点值是 **0** —— **和 minimax 完全一致**。

但注意中间值不一样了：minimax 说 A 是 −1（"X 输"），negamax 说 A 是 +1（"**轮到 O 走的那个局面对 O 有利**"）。**同一个局面，换了立场，值就换了符号。** 这就是"视角统一"：negamax 永远回答"**该走的那个人**有多好"。

### 代码对比

```python
# ❌ minimax：两套循环，只有 max/min 不同
if depth % 2 == 0:
    best = -2
    for i in ...:
        best = max(best, self._minimax(cells, depth + 1))
    return best
else:
    best = 2
    for i in ...:
        best = min(best, self._minimax(cells, depth + 1))
    return best
```

```python
# ✅ negamax：一套循环，一个负号
best = -2
for i in ...:
    cells[i] = player
    value = -self._search(cells, 3 - player, depth + 1, -beta, -alpha)
    cells[i] = EMPTY
    if value > best:
        best = value
return best
```

四个东西变化了，逐个说清：

| 变化               | 说明                                                       |
| ---------------- | -------------------------------------------------------- |
| `depth % 2` 判断没了 | 改成显式传 `player`（1 或 2）。**不用再靠"深度的奇偶"推断轮到谁**               |
| `3 - player`     | 小技巧：1 ↔ 2 互换（3−1=2，3−2=1）。比写 `X if player == O else O` 短 |
| 少了 `min` 那一支     | 对手的"最小"变成了"他取最大 + 我取负"                                   |
| 多了一个 `-`         | 就这一个负号，替掉了整个 else 分支                                     |

（代码里多出来的 `-beta, -alpha` 是 K2.4 的剪枝窗口，现在先当作不存在：它就是 `-2, 2` 的传递版本。）

### 为什么能省一半代码 —— 更重要的原因

省代码只是表象。真正的收益是**视角统一**带来的"不会错"：

|         | minimax                         | negamax         |
| ------- | ------------------------------- | --------------- |
| 返回值含义   | 永远"以 X 为准"                      | 永远"**以该走的人为准**" |
| 调用者要做什么 | 必须记住"我是 X 还是 O"，再决定取 max 还是 min | 无条件取最大          |
| 传参      | 不用传 `player`，靠 `depth` 推        | 显式传 `player`    |
| 出错方式    | 视角搞反 → **符号系统性反了**，但程序照跑        | 视角只有一个，反不了      |

> **minimax 的符号搞反是最高频的 bug**，而且它**不会报错** —— 你会得到一个"每一步都选最差走法"的 AI，看起来很聪明，实际上在自杀。
> negamax 从结构上消灭了这种 bug。这就是"**设计让错误不可能发生**"的例子，比"加注释提醒自己别搞错"高一个层次。

## K2.4｜alpha-beta 剪枝（本课核心）

### 为什么要它

现在 AI 会下棋了，而且下得完美。但它是**用 54 万个节点换来的 0.38 秒**。在井字棋上这没问题 —— 可 K2.5 你会看到，换成五子棋，节点数会涨到"宇宙都装不下"。

所以我们现在就要问一个问题：**那 54 万个节点里，有多少是白算的？**

答案是：**大部分**。

### 剪枝的直觉（先看这个，再看公式）

假设你是一个棋手，正在考虑两步：A 和 B。

- 你看了 A：发现对手有一个应对会让你**输**（A 的结果是 −1）
- 现在你开始看 B。刚看了 B 的第一个应对，发现它给你 **0（平局）**

**问题：B 剩下的那些应对，你还需要看吗？**

**不需要了。** 因为：

- 你已经知道 **A 只能给你 −1**
- 现在你**至少**能拿到 0（B 的第一个应对就给了 0）
- 而 B 剩下的应对**只会让 B 变得更差或一样**（对手会选对他最好的，也就是对你最差的）
- 所以 B 的最终值必然 **≤ 0**，但 **0 > −1**，**B 一定比 A 好**
- **不管 B 剩下那些应对是什么，你都会选 B**

**后面那些应对，看了也不影响决定。** 这就是剪枝。

### 两个数字：α 和 β

把上面的推理写成变量：

| 符号           | 含义                    | 站在"当前该走的人"的立场 |
| ------------ | --------------------- | ------------- |
| **α**（alpha） | **我已经保证能拿到的分数的下界**    | "至少这么高"       |
| **β**（beta）  | **对手已经保证能把我压到的分数的上界** | "最多这么高"       |

剪枝条件：

```
α ≥ β   →   剪掉！
```

**怎么理解 α ≥ β**：

> "我最差也能拿到 α"，但"对手能把我限死在 β"，而 **α 已经不比 β 差了** ——
> 也就是说，**不管这里再往下算多少，答案都不会改变上一层的选择**。所以停。

换个更口语的说法：

> **β 是"这条分支最多值这么多"（对手的否决线）**
> **α 是"外面已经有更好的选择了"（我的最低要求）**
> 当"最多" ≤ "最低要求"，这条分支就没用了。

### 一张图看懂剪枝过程（还是那棵 6 节点小树）

```
                    [根: X走]  α=-∞ β=+∞
                   ╱                ╲
        [A: O走] α=-∞ β=+∞      [B: O走] α=0 β=+∞
        ╱        ╲                ╱        ╲
    叶:+1      叶:-1          叶:0      叶:+1
    ①           ②              ③         ④（被剪）
```

| 步   | 发生什么                                                   | α / β 变化                     |
| --- | ------------------------------------------------------ | ---------------------------- |
| ①   | 看 A 的第一个叶子，值 +1。O 走，所以"最多让 X 拿到 +1"                    | A 的 β = min(+∞, +1) = **+1** |
| ②   | 看 A 的第二个叶子，值 −1。−1 < +1，O 会选这个                         | A 的 β = **−1**               |
| —   | A 算完：**A = −1**。根是 X 走，把已知的好结果记下来                      | 根的 α = max(−∞, −1) = **−1**  |
| ③   | 进 B，看第一个叶子，值 0。O 走 → B 的 β = 0                         | B 的 β = **0**                |
| ④   | 此刻：**X 在外面已经有 −1 兜底**（根 α = −1），而 **O 已经能保证把这里压到 ≤ 0** | → **剪枝，第四个叶子不看**             |

**第 ④ 步为什么成立**（很多教程在这里含糊过去）：

- 在节点 B（轮到 O），O 已经找到一个"让 X 只拿到 0"的办法
- 根节点上，X 已经有一个选择 A，能给 X 拿到 **−1**
- X 在根节点取 max：`max(−1, B的结果)`
- 关键：**不管 B 的结果是 0、−1 还是更差，X 都会选"更大的那个"**
  - 如果 B ≤ −1：X 选 A（都是 −1，无差别）
  - 如果 B = 0：X 选 B
  - **两种情况都不影响"X 会选什么"这个决定**
- 而"X 会选什么"才是搜索的目的。**B 剩下的叶子最多只能让 B 从 0 变得更差 —— 而"更差"不改变 X 的选择。**
- 所以剩下的不用看。**剪掉。**

看出来了吗？**剪枝的正确性论证，靠的就是"外面已经有一个更好的选择了"。** 这就是 α 的作用。

> ⚠️ **本课最容易想不通的地方就在这里。** 很多人以为"剪枝是因为那些分支不重要"。
> **不是。** 剪枝是因为：**那些分支的结果已经不可能改变上层的选择了。**
> 一字之差，理解深度差一层楼。出关测验的核心题就考这个。

### 代码：只多了三行

完整代码在 `engine.py` 的 `AlphaBetaAgent`。相对 negamax，只多了这些：

```python
def _search(self, cells, player, depth, alpha, beta):
    ...
    best = -2
    for i in self.ordering(legal_moves):
        cells[i] = player
        value = -self._search(cells, 3 - player, depth + 1, -beta, -alpha)   # ← ① 负号传参
        cells[i] = EMPTY

        if value > best:
            best = value
        if best > alpha:
            alpha = best                                                     # ← ② 抬高下界
        if alpha >= beta:
            self.stats.cutoffs += 1
            break                                                            # ← ③ 剪枝
    return best
```

三个新东西：

| ① `-beta, -alpha` | 传给子节点时**取负并对调**。因为子节点是"对手的立场"，我的上界就是他的下界 |
| ② `alpha = max(alpha, best)` | 我找到了更好的，把"至少能拿到"抬高 |
| ③ `if alpha >= beta: break` | 我的下界已经压过对手的上界 → 这条分支没用了，**跳出循环** |

> **`-beta, -alpha` 这个对调是 negamax 里最容易写错的一处。**
> 记法：在"我的立场"里，`alpha` 是下界、`beta` 是上界；到了对手那里，**他的下界就是我的上界**，所以要写成 `(-beta, -alpha)`。
> 写反了（写成 `-alpha, -beta`）程序照样跑、照样出结果 —— 只是**有时候会剪错**。所以下面第一件事就是**用"结果必须和非剪枝版完全一致"来验证它**。

<summary>答案</summary>

- 进 A（O 走，β = +∞）：

  - 第二个叶子 +1 → +1 > −1，O 不会选它，β 不变
  - **A = −1**
- 回到根：α = max(−∞, −1) = **−1**
- 进 B（O 走，把 X 的 α = −1 传下去，O 的 β 初始为 +∞）：
  - 第一个叶子 −1 → β = min(+∞, −1) = **−1**
  - 现在检查：**α（−1）≥ β（−1）成立** → **剪枝！B 的第二个叶子不会访问**

**再验证一遍我们的结论**：不剪枝的话，B = min(−1, +1) = −1。剪枝版"以为"B ≤ −1。
根 = max(A=−1, B≤−1) = **−1**，两种算法给的**根答案完全一致** ✅

## K2.5｜分支因子与深度爆炸

### 为什么要它

井字棋我们赢了 —— 搜到终局，完美，还快。现在把目标换成五子棋（这是我们从 L03 开始的主战场）。

**这一节就是让你亲眼看到：为什么井字棋的那套做法，到五子棋上会彻底失效。**

这个"失效"不是挫折，它是**整个教程后面 12 课存在的唯一理由**。

### 分支因子 b，深度 d，节点数 ≈ b^d

**分支因子**（branching factor）= 平均每一步有几个可选走法。

| 棋       | 棋盘    | 开局分支因子 | 平均分支因子                     |
| ------- | ----- | ------ | -------------------------- |
| 井字棋     | 3×3   | 9      | ~5（有赢棋提前终止）                |
| **五子棋** | 15×15 | 225    | **~30–60**（可用格子在增长，但很多是废点） |
| 国际象棋    | 8×8   | 20     | ~35                        |
| 围棋      | 19×19 | 361    | ~250                       |

搜索树的大小大致是 **b^d**（要看 d 层）。

### 手算一下五子棋

我跑过（`measure.py` 的【4】）：

```
分支因子 30：
   深度  4 层 ->                       810,000 个局面
   深度  6 层 ->                   729,000,000 个局面
   深度  8 层 ->               656,100,000,000 个局面
   深度 10 层 ->           590,490,000,000,000 个局面

分支因子 60：
   深度  4 层 ->                    12,960,000 个局面
   深度  6 层 ->                46,656,000,000 个局面
   深度  8 层 ->           167,961,600,000,000 个局面
   深度 10 层 ->   604,661,760,000,000,000 个局面
```

**对照一下这些量级**：

| 量级       | 是什么                           |
| -------- | ----------------------------- |
| 10³      | 一千                            |
| 10⁶      | 一百万                           |
| 10⁹      | 十亿（全世界人口数量级）                  |
| **10¹¹** | **银河系恒星数量**                   |
| **10¹²** | **五子棋搜 8 层（b=30）** ← 比银河系恒星还多 |
| 10¹⁸     | 五子棋搜 10 层（b=60）               |
| 10⁸⁰     | 可观测宇宙的原子总数                    |

**五子棋搜 8 层，节点数超过银河系的恒星数。** 而"8 层"在五子棋里意味着什么？意味着**只看 4 个回合**。五子棋的高手要看十几步。

假设计算机每秒算 1 亿个局面（这个速度在 Python 里根本达不到，我们假设是 C++）：

```
6.5 × 10^11 ÷ 10^8 = 6500 秒 ≈ 1.8 小时    ← 下一手棋
```

**一步棋算两个小时，而且还只看 4 个回合。** 这条路死了。

### 那 alpha-beta 能救吗？

能救一部分 —— 剪枝的效果是 **b^d → b^(d/2)** 量级（完美排序时）。也就是**同样的时间能看两倍的深度**。

代入五子棋：

```
不剪枝：30^8  ≈ 6.6 × 10^11
剪枝后：30^4  ≈ 8.1 × 10^5     ← 看着不错！
```

但问题在于：**"完美排序"是理想情况。** 真实情况下你能砍掉 90% 的分支就已经很好了，而且：

1. 五子棋的**评估函数**你还没有（搜到终局不可能，必须"猜"）
2. 就算搜了 8 层，8 层之后的棋你完全看不见 —— **而在五子棋里，8 层之内看不出胜负是常态**
3. 真正的五子棋高手要看到 **十几层甚至几十层**

**所以现实的答案是：剪枝让我们从"完全没戏"变成"有点戏"，但它一个人解决不了问题。**

后面的课程会一层层加上去：

| 课       | 加什么                      | 解决什么             |
| ------- | ------------------------ | ---------------- |
| L07     | **棋型特征**                 | 让评估函数真的懂"活三""冲四" |
| L08     | 迭代加深 / 走法排序 / 置换表 / 静态搜索 | 让同样的时间搜得深得多      |
| L09–L10 | 值函数 + 自对弈                | 让"猜"变成"学出来的"     |
| L12     | MCTS                     | 换一条完全不同的路        |
| L13–L14 | 神经网络 + PUCT              | AlphaZero 那条路    |

### 一个反直觉的事实：井字棋为什么不是"小一号的五子棋"

你可能会想："那把井字棋的方法直接放大到五子棋不行吗？"

不行，而且原因很根本：

|           | 井字棋             | 五子棋              |
| --------- | --------------- | ---------------- |
| 能搜到底吗     | **能**（5478 个局面） | **不能**（10¹¹ 是起步） |
| 结果        | **确定**的胜负 / 平局  | 只能**估计**         |
| 需要的核心能力   | 搜索              | **评估 + 搜索 + 学习** |
| 有没有"标准答案" | 有（可以拿来验证 AI）    | 没有（只能靠对战胜率）      |

**井字棋的教学价值，恰恰在于它有标准答案**：你现在可以用它来检查任何搜索算法的正确性。等到了五子棋，那个标准答案就没了 —— 你只剩"跟别人下，看胜率"这一条路。

> **这就是为什么 L03 要学"从数据学评估函数"。** 手工评估（下面 K2.6）已经要开始了，而它很快就会让你绝望。

## K2.6｜限深搜索与手工评估函数

### 为什么要它

K2.5 撞墙了。墙上是四个字：**搜不到底**。

那怎么办？只有一个办法：

> **别搜到底。搜到某一层就停下，然后"猜"一个分数。**

这个"猜"的函数叫**评估函数**（evaluation function）—— 你已经见过它的另一个名字了：

> **它就是我们整个教程后来要学的那个东西。** L03 的线性回归、L04 的逻辑回归、L06 的 GBDT、L13 的神经网络，**全都是在造更好的评估函数**。

所以这一节是**从"搜索"跨到"机器学习"的那一步**。你现在手写一个评估函数，然后亲手体会到它有多不好用 —— 那种"难受"，就是 L03 存在的理由。

### 限深搜索：把"搜到底"改成"搜 N 层"

改动小得惊人：**递归基多一个**。

```python
def _search(self, cells, player, depth, alpha, beta):
    w = winner(cells)
    if w is not None:              # 递归基 1：有人赢
        return 1 if w == player else -1
    if is_full(cells):             # 递归基 2：下满了
        return 0
    if self.max_depth is not None and depth >= self.max_depth:
        return _eval_to_value(evaluate(cells, player))    # ← 递归基 3：到深度上限，猜
    ...
```

**三行，性质完全不同**：

| 递归基       | 返回什么    | 可信度           |
| --------- | ------- | ------------- |
| 有人赢       | ±1      | **确定**（这是真值）  |
| 下满了       | 0       | **确定**        |
| **到深度上限** | 评估函数的输出 | **猜测**（可能是错的） |

### 手工评估函数：数"每条线上的潜力"

先看最笨的版本（`eval_functions.py` 的 `material_score`）：只数双方各有几个子。

```python
def material_score(cells, player):
    return (cells.count(player) - cells.count(3 - player)) / 9.0
```

在井字棋里这个函数几乎没用 —— 双方子数最多差 1，而且"子多"和"要赢"完全是两回事。**写出来是为了让你看到评估函数可以有多笨。**

稍微认真一点的版本：**看每条连线上的潜力**。

```python
def evaluate(cells, player):
    score = 0.0
    for a, b, c in LINES:          # 8 条线
        mine = 0; theirs = 0
        for idx in (a, b, c):
            v = cells[idx]
            if v == player:      mine += 1
            elif v != EMPTY:     theirs += 1
        if mine and theirs:
            continue               # 这条线双方都有子，废了，0 分
        if mine:
            score += mine * mine             # 我在这条线上的威胁
        elif theirs:
            score -= theirs * theirs         # 对手在这条线上的威胁
    return score / 20.0
```

三个设计决定，每个都有理由：

| 决定                            | 理由                                          |
| ----------------------------- | ------------------------------------------- |
| 双方都有子 → 这条线记 0 分              | 谁也在这条线上赢不了                                  |
| 用 `mine * mine`（平方）而不是 `mine` | "2 个子在一条线上"比"1 个子"危险得多（差一步就赢）。平方让 2→4，把差距拉开 |
| 除以 20                         | 把数值缩到 1 附近，好和 ±1 混用                         |

**注意这些权重（平方、除以 20）全是我拍的。** 这就是"手工评估函数"的含义：**我凭直觉定规则，凭感觉调数字。**

### 实测：手工评估有多难受

我跑了四组实验，每一组你都该亲手复现。

**实验 1：限深 AI vs 随机对手**

```
限深 1 层：胜 280 / 负 3 / 平 17   得分率 96.2%
限深 2 层：胜 275 / 负 0 / 平 25   得分率 95.8%
限深 3 层：胜 286 / 负 1 / 平 13   得分率 97.5%
限深 4 层：胜 277 / 负 0 / 平 23   得分率 96.2%
限深 5 层：胜 273 / 负 0 / 平 27   得分率 95.5%
限深 6 层：胜 279 / 负 0 / 平 21   得分率 96.5%
```

**看上去很棒？别急。** 随机对手本来就是最弱的对手。真正的问题是下一组。

**实验 2：限深 AI vs 完美 AI（换边，各 200 局）**

```
限深 1 层（奇数：评估在对手回合调用）：胜 0 / 负 32 / 平 168   得分率 42.0%
限深 2 层（偶数：评估在自己回合调用）：胜 0 / 负  0 / 平 200   得分率 50.0%
限深 3 层（奇数）：                  胜 0 / 负 15 / 平 185   得分率 46.2%
限深 4 层（偶数）：                  胜 0 / 负  0 / 平 200   得分率 50.0%
限深 5 层：                          胜 0 / 负  0 / 平 200   得分率 50.0%
```

（换三组随机种子各跑 400 局，结论一致：奇数深度每次都输 26~86 局，偶数深度从不输。）

**看到那堵墙了吗？**

1. **限深的 AI 会输棋** —— 而"搜到终局"的版本从不输。这就是"猜测"的代价。
2. **深度的奇偶会影响胜负**（42% → 50% → 46% → 50%）。这不是玄学，是因为**评估函数在"谁的回合"被调用，效果完全不同** —— 奇数深度时，评估函数是在**对手刚走完**的位置上打分，那个位置上"对手的威胁"还没被回应，会被低估。
3. **加深到 4 层以后就不再进步了**（都是 50%）—— 因为井字棋本身太简单，4 层足够看清大部分局面。这说明"加深度"也有天花板。

> **那 50% 是什么？** 得分率 = (胜 + 0.5×平) / 总局数。**50% 就是"全是平局"**。也就是说偶数深度的限深 AI 在 200 局里**一局都没输**（但也一局没赢）—— 它和完美 AI 打平了。
> 
> 😑 **等一下，那它岂不是很强？**
> 是的，在井字棋上"限深 2 层 + 这个评估函数"已经够用了。**但这恰恰是井字棋太简单的证据。** 换成五子棋，这个评估函数会被打得很惨 —— 因为它对"活三""冲四"一无所知。
> 
> 所以这一节的结论不是"评估函数没用"，而是：**在简单的棋上你手工调调就够了，在复杂的棋上手工调根本调不动。** 而"调不动"的具体感受是这样的 ↓

**实验 3：调参的绝望时刻**

现在你想让评估函数更好。你会开始加特征、调权重：

```python
def evaluate_centered(cells, player):
    base = evaluate(cells, player)
    WEIGHT_CENTER = 0.05          # ← 为什么是 0.05？不知道，试出来的
    WEIGHT_CORNER = 0.02          # ← 为什么是 0.02？也不知道
    if cells[4] == player:
        base += WEIGHT_CENTER
    ...
    return base
```

**然后你会发现三件事**：

1. **`0.05` 应该是多少？** 你不知道。试了 0.03、0.05、0.1，胜率"感觉"变化不大（因为井字棋本来就够用）。
2. **加了"占中心加分"之后，会不会和"线上的潜力"重复计算？** 可能会。中心本来就在 4 条线上。
3. **加了这么多特征，我该怎么知道哪个真的有用？** 你只能**一次加一个、跑几百局**。加到第 10 个特征时，你已经不知道哪个重要了。

**这就是"手工评估函数"的真实体验：** 每一步都能走，但**你没有任何办法知道下一步该往哪走**。你只有一双手和一个"感觉"。

**实验 4：AI 自己觉得它要走多久**

```
限深 1 层           开局第一步：0.0 毫秒，看了 9 个局面
搜到终局（完美）     开局第一步：20.0 毫秒，看了 15705 个局面
```

（15705 而不是 7275，是因为 `choose()` 要对**每个**候选走法算一次价值，加起来是 15705。）

### 手工评估在五子棋上会怎样

把上面那个 `evaluate()` 直接搬到五子棋？**它会彻底失败。** 因为：

| 五子棋里重要的                  | 这个评估函数能看出来吗    |
| ------------------------ | -------------- |
| 活三（两头没堵的三连，下一步成活四必胜）     | ❌ 它只看"这条线谁占得多" |
| 冲四（一头被堵的四连，必须立刻堵）        | ❌              |
| 眠三 / 活二 / 双威胁            | ❌              |
| **"我有活三，但对手有冲四"（顺序很重要）** | ❌ 它只会把两边分数相减   |

**换成五子棋，你需要的是"数出 8 个方向上的棋型"，然后给每种棋型配权重。** 那是 L07 的内容。而就算你写出了那套特征，**权重还是得靠拍** ——

**除非让机器自己从数据里学出来。** 那就是 L03。

## N. 常见错误对照表（本课版）

| 现象 / 报错                                            | 原因                                             | 解法                                             |
| -------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------- |
| AI 每一步都选最差、像是在自杀                                   | negamax 的**符号**写反，或 minimax 的 max/min 搞反了      | 用空盘验：价值必须是 `0`；再用"X 已经走中心+边"那个局面验：必须是 `-1`     |
| `ModuleNotFoundError: No module named 'board'`     | 忘了 `import _paths`，它的作用是把 part1 加进模块搜索路径       | 在任何 part1 模块的 import **之前**先 `import _paths`   |
| 搜出来的走法老是同一个                                        | 同分走法没随机化                                       | `choose()` 里用 `random.choice(best_moves)`      |
| 加了剪枝后结果变了                                          | 剪枝参数传反了（`-alpha, -beta`）或 `break` 位置不对         | **必须用"剪枝版 vs 不剪枝版结果逐位相同"来验证**                  |
| 棋盘被"试走"污染，后面的判断全错                                  | 忘了 `pop()` / 忘了清空格子                            | 每个 `push` 后面都要有对应的 `pop`；用 L01 的"试走 → 撤回"循环测一遍 |
| `RecursionError: maximum recursion depth exceeded` | 递归基没写全（常见：忘了 `is_full`，或者限深判断写成了 `>` 而不是 `>=`） | 三个递归基一个都不能少                                    |
| 限深搜索比不设深度还慢                                        | `max_depth` 判断写在了循环里面而不是递归入口                   | 判断必须在函数开头                                      |
| 胜率统计没意义                                            | 没有换边（先手优势巨大）                                   | `match(..., both_sides=True)`                  |
| 限深 AI 的"分数"看起来很小（如 0.2）                            | 那是**评估函数的内部打分**，不是胜率                           | 想知道棋力，只能看对战胜率                                  |

```python
import sys; sys.path.insert(0, ".")
import _paths
import itertools

from constants import EMPTY, X, O
from rules import winner, is_full

def all_reachable_boards(max_depth=6):
    """穷举出所有"还没分出胜负"的局面（深度 ≤ max_depth）"""
    out = []
    def walk(cells, depth):
        if winner(cells) is not None or is_full(cells):
            return
        out.append((tuple(cells), X if depth % 2 == 0 else O))
        if depth >= max_depth:
            return
        for i in range(9):
            if cells[i] == EMPTY:
                cells[i] = X if depth % 2 == 0 else O
                walk(cells, depth + 1)
                cells[i] = EMPTY
    walk([EMPTY] * 9, 0)
    return out

from board import Board
boards = all_reachable_boards()
print("待检查局面数：", len(boards))

pruned = AlphaBetaAgent()
raw = AlphaBetaAgent(use_pruning=False, ordering=lambda m: m)
same = 0
for cells, player in boards:

    b.cells = list(cells)
    b.history = [0] * (9 - cells.count(EMPTY))
    v1 = pruned.value(b)
    v2 = raw.value(b)
    if v1 == v2:
        same += 1
    else:
        print("❌ 不一致：", cells, player, v1, v2)
        break
print("一致：%d / %d" % (same, len(boards)))
```

### 实操 3：埋下 L03 的种子（10 分钟）

写一个最简单的评估函数，**故意只用一个特征**：

```python
# 在 notes/ 里写，不用改 eval_functions.py
def evaluate_one_feature(cells, player):
    """只数：我有几个子，减去对手有几个子。别的什么都不看。"""
    return (cells.count(player) - cells.count(3 - player)) / 9.0
```
